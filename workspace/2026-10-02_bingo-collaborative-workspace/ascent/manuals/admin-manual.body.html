BCW and the Ascent: Administrator Manual

Bingo Collaborative Workspace V0.17, the Ascent GX10 AI server and the HAL3000 tools. For the ICPM and whoever looks after the system. November 2026.

This manual explains what the system can do and how to run it day to day. It is written for administrators, not programmers. Everyday features (the Assistant, Library search, calendar, reporting) are explained in the User Manual; this manual covers setting up, looking after and fixing the system.

2. Everyday care

Daily: is everything up?

Double-click Ascent status on HAL3000's desktop (installed by the Tools package, section 9). It checks every service and says in plain words what is up or down:

  • the Ascent on the network;
  • chat, with the model loaded;
  • Library search;
  • Docling;
  • ComfyUI;
  • Gitea;
  • SSH;
  • BCW itself.

"Everything is answering." means all is well.

In BCW, Tools → Admin → Site overview shows:

  • the release;
  • the last backup;
  • service health;
  • any outstanding administration operations.

Check work LAN there tests the network without changing anything.

Weekly: back up

BCW has no automatic backup.

  1. Take one at least weekly, and always before an update: Tools → Admin → Version & backups → Backup now.
  2. Regularly copy a backup off HAL3000 with BCW Maintenance → Export backup to a USB drive (section 7).

As needed

  • Approve new Library documents (Project → Library → Waiting for approval).
  • Check Failed reads and Uncertain in the Library.
  • Set up accounts as people arrive and leave.
  • Create the weekly reporting cycle.

Switching on and off

  • Switching on:
    1. Plug a network cable into either wired port, then press the power button.
    2. The Ascent takes the address 192.168.2.45 by itself.
    3. Allow about 5 minutes before the models are ready. Then run Ascent status.
  • Shutting down safely:
    1. Warn users first: AI answers in progress will stop.
    2. From PowerShell on HAL3000, run ssh bmt01@192.168.2.45, then sudo poweroff.
    3. Wait for the lights to go out before unplugging.
    Avoid simply pulling the power.
  • Restarting: the same as shutting down, but with sudo reboot. Allow about 5 minutes afterwards.

The AI models

The Ascent holds one chat model at a time. Choosing a different model in BCW makes the Ascent swap, which takes a minute or two. The swap affects everyone, including OpenCode and Codex.

Model nameUseNotes
inkling-2-miniDefault; keep this. Good all-rounder for the Assistant, reviews, reports and coding.About 28 words a second. Handles very long conversations (262,144 tokens). Two answers at once. Leaves room for images to run alongside chat.
flash-nextFallback if Inkling disappoints on a task.Similar speed; conversations up to 131,072 tokens (half Inkling's). Fills the Ascent's memory. Tick Pause chat while images are made while using it (section 6).
gpt-oss-120bFallback.Text only.
qwen3.8-27bSpare.Slow (about 7 words a second).

After using a fallback, switch BCW back to inkling-2-mini, and untick the image pause again if you ticked it for Flash-Next. If you leave BCW conversation context tokens blank, BCW adjusts to each model's limit by itself.

Managing the Ascent

Day-to-day management needs no login. If a service is down, you can restart it from HAL3000:

  1. Open PowerShell and run ssh bmt01@192.168.2.45. Enter the bmt01 password.
  2. Restart the service that is down:
    DownCommand
    Chatsudo systemctl restart llama-chat (allow 2 minutes)
    Library searchsudo systemctl restart llama-retrieval
    Imagessudo systemctl restart comfyui
    Document readingsudo docker restart docling
    Giteasudo docker restart gitea
  3. Type exit to leave, and run Ascent status again.

Rules for the Ascent:

  • Automatic updates are off on purpose. Leave them off.
  • Never delete or move files in its models folder: they can't be downloaded again on site.
  • Don't install NVIDIA drivers.
  • New software must be built for arm64; ordinary Windows or PC (x64) programs won't run on it.
  • Make bigger changes at home, or with a prepared kit.

If the Ascent misbehaves: the recovery ladder

  1. Restart the one service that is down (above).
  2. Restart the whole Ascent (sudo reboot).
  3. Restore that service's settings from the Ascent's saved configuration. The ascent-admin instructions on the Ascent describe this, and Codex on the Ascent can do it.
  4. Reinstall the component from the Ascent's own offline kit (~/offline).
  5. Restore a full disk image, if one has been taken, or use the ASUS factory recovery USB. This is a last resort: it erases the Ascent, which must then be rebuilt.

Steps 3 to 5 are specialist work. Write down the exact messages first.

4. Connecting BCW to the Ascent

Do this once after installing or updating V0.17, or whenever the Ascent's address changes.

Check the Ascent answers

On HAL3000, open http://192.168.2.45:8080/v1/models in a browser. A list of models with inkling-2-mini among them means BCW can reach it. If nothing loads, check:

  • the cable;
  • that HAL3000's own address starts with 192.168.2 (run ipconfig);
  • that no other device uses 192.168.2.45.

Chat: the Model server

  1. Sign in as an ICPM. Open Tools → Admin → Model server and press Edit.
  2. Model server URL: http://192.168.2.45:8080/v1
  3. Press Load available models and choose inkling-2-mini as the Chat model.
  4. Leave BCW conversation context tokens blank (it then uses the full 262,144). Leave Temperature, Top-p, Maximum output tokens and Thinking at their defaults.
  5. Press Save model settings, then Check BCW compatibility. It runs a safe test with made-up data and should pass.

Model settings can't be changed while anyone's Assistant is working. Try again when it is quiet. The same panel also appears under Daily Brief → Agent settings → Local model configuration.

Library and images: Ascent services

  1. Open Project → Library → Ascent services (last tab, ICPM only).
  2. Enter:
    • Docling address: http://192.168.2.45:8793
    • Retrieval server address: http://192.168.2.45:8081
    • ComfyUI address (image edits): http://192.168.2.45:8188
  3. Leave Pause chat while images are made unticked while Inkling is the model.
  4. Press Save Ascent services. The Library database badge should read "schema 1 of 1" in green.

Proving it works

A five-minute acceptance test:

  • a Library search that shows an Open original at page N link;
  • an Assistant question answered with citations;
  • one Preliminary Review;
  • one Word document from the Assistant;
  • one image, with a View link in the conversation.

Adding a user

  1. Open User accounts → Create user.
  2. Fill in:
    • Username: lowercase, starting with a letter;
    • Person profile: choose an existing person or create one;
    • Display name;
    • Contact email;
    • Assigned roles.
  3. Set a password of at least 15 characters. It works for BCW, Nextcloud and OpenProject.
  4. Confirm with Your administrator password.

Laptop accounts BMT01 to BMT08 always exist and can't be deleted. To hand one to a new occupant, use Resources → Accounts. The handover keeps the account's password, content and settings, so set a new password if the previous occupant knew it.

Looking after accounts

Open a user's card:

  • Set password: a new password; signs them out everywhere.
  • Unlock login: after too many wrong passwords.
  • Disable access / Enable access: blocks or restores sign-in. Their work is kept.
  • Sessions → Revoke all sessions: signs them out of every device.
  • Archive account: permanent. The username can't be reused.

If a card shows Administration pending, Nextcloud or OpenProject didn't confirm the change. Open Administration operations, choose the item and press Retry same operation. Don't start a different change to work around it.

Roles and permissions

The roles are ICPM, ICSS, Marine/Mechanical, Electrical, NavArc, Overflow01–03 and Senior Engineer. A person can hold several roles, and gets the highest permission of any of them.

Role permissions sets each feature to none, view or edit per role. The features are:

  • Project work, MCM, Project calendar, Routines & reminders;
  • Reporting, Files, Conversations, Codex assistant;
  • Team & accounts, Resources, Operations, Library.

The defaults are:

  • Resources: ICPM only.
  • MCM and Library: edit for ICPM and Senior Engineer, view for everyone else.
  • Everything else: edit for all roles.
  • Always ICPM only: Admin, role assignment, Agent settings and Ascent services.

Changes apply on the user's next click.

Forgotten ICPM password

On HAL3000, signed in as the Windows user who owns BCW's data:

  1. Open BCW Maintenance and choose Recover administrator access.
  2. Enter an existing ICPM username and a new password.
  3. Press Check / Preview, then Run selected action.

6. Library administration

First-time setup

  1. On Mother, create a folder called Library with six folders inside: 01 Standards, 02 Specifications, 03 Procedures, 04 Manuals, 05 Drawings and 06 Reports. Under 06 Reports, make one folder per subject.
  2. Copy in documents named DocNo_Rev_Title, e.g. PRO-0007_R01_Tank inspection procedure.docx.
  3. Press Library → Sources → Scan now.
  4. Approve the governing documents under Waiting for approval. Select all on this page and Approve selected handle up to 500 at a time.

The Library tabs

TabWhat you do there

Other document folders

Add network folder adds another shared folder, such as \\SERVER\Share\Folder. You set its category, its file naming and whether each document needs approval.

  • BCW reads it with the Windows account it runs under, so that account needs read access.
  • Removing a source takes its documents out of search but keeps past citations.
  • Mother's Library can be paused but not removed.

Good practice

  • A revised document goes in as a new file with a new revision number. Never overwrite the old one.
  • BCW never changes the original files. Tidy them on Mother itself, then Scan now.
  • Files over 50 MB are not read. Split very large scans.

Images

With Inkling as the chat model, images run alongside chat and take about a minute each. Leave Pause chat while images are made off.

Tick it only if you switch the chat model to flash-next, which fills the Ascent's memory. BCW then pauses chat for about three minutes for each batch of images.

Image jobs also wait if OpenCode or Codex keeps the Ascent busy for a long time.

7. Backups, updates and recovery

All maintenance is done on HAL3000 with BCW Maintenance, which you start from C:\BCW\Maintenance.ps1 or from an update USB. Every action works the same way:

  1. Choose the action.
  2. Press Check / Preview and read what it will do.
  3. Press Run selected action.

Maintenance refuses to start while people are working: it says so, for example "BCW has active work; finish it before maintenance". Ask users to finish their Assistant chats and close Office and Access files, then try again.

Where things are

  • Program: C:\BCW
  • Data: Documents\BCW\data in the BCW Windows user's folder
  • Backups: Documents\BCW\data\backups

Backups

  • Taking a backup: use Backup now under Tools → Admin → Version & backups, or Maintenance → Backup.
    • It covers everything: records, accounts, AI history, documents and the Library.
    • BCW pauses briefly while it runs.
    • Every backup is checked.
  • Copying it off HAL3000: Maintenance → Export backup to an empty folder on a USB drive. Keep it somewhere safe: it contains passwords and private records.
  • What doesn't count: copying the data folder by hand while BCW runs is not a backup.
  • Old backups: nothing deletes them automatically. Check free space now and then.

Restoring

  • Restore puts the system back to a chosen backup. It first takes a safety backup of the current state. Anything done since the chosen backup is lost.
  • Restore into fresh target is for a replacement PC.
  • Leave "Restore only: also replace shared Mother documents" unticked unless you really mean to overwrite Mother.

Updating BCW from a USB kit

  1. Pick a quiet time. Take a backup.
  2. Ask users to finish and save their work.
  3. Plug in the update USB and run UPDATE-BCW-V0.17.bat (or the batch file for the new version) at its root. It checks the kit and opens Maintenance.
  4. Choose Update, the existing installation and the release folder on the USB. Never choose Install over an existing system.
  5. Press Check / Preview. Confirm the versions, the data location and that a backup will be taken.
  6. Press Run selected action. It copies and checks the new release, backs up, upgrades the data and restarts the services.
  7. Reopen BCW from its usual launcher. Check the version under Version & backups, and that records and chats are there.

Updating to the same or an older release is refused ("Update must be a newer release; use Restore for rollback"). To go back to an earlier state, use Restore.

If something is interrupted

After a power cut or crash during maintenance, use Recover interrupted update or Recover interrupted maintenance. Never delete lock or marker files by hand.

Starting BCW

Run C:\BCW\Start.ps1 -Open, or use BCW's usual launcher. It starts BCW if it isn't running and opens the window.

8. Other connections and settings

Mother

Tools → Admin → Mother connection:

  1. Enter the Shared folder address (e.g. \\MOTHER\Documents) and the Share access type.
  2. Press Test connection, then Connect Mother.
  • BCW can read Mother and add new files to it. It can't change, move or delete existing files.
  • Selected folder sharing shows one subfolder, read-only, to chosen accounts in Nextcloud as "Mother Shared".

MCM (Access risk database)

Tools → Admin → MCM connection → Edit:

  1. Set the File path on BCW host.
  2. Tick Enable this source.
  3. Press Save source settings, then Test saved connection.

Editing from BCW also needs Allow editing according to role permissions.

Mail and the Daily Brief

Daily Brief → Agent settings holds the agent mailbox and the list of approved recipients (up to ten mail.local addresses).

  1. Press Review mail settings, then Approve these mail settings.
  2. Test with Test saved mail connection · no send.

An automatic daily email needs its own schedule approval on the Daily Brief page.

Access from laptops (HTTPS)

Staff laptops reach BCW at https://192.168.2.35.

  • Certificate: HAL3000's certificate is set up with the kit's INSTALL-BCW.bat, option 5 — Set up / renew offline LAN HTTPS. It lasts 397 days: renew it with the same option before it runs out.
  • Laptops: on each laptop, run Trust-BCW-Https.bat from data\https\public. Check that the fingerprint matches, then type TRUST.
  • If laptops can't connect: run Check work LAN in Site overview. Windows may have switched HAL3000's network to "Public".

Routines, resources and reporting

  • Routines: the ICPM can assign routines to others and see All team routines. After a laptop handover, reassign the previous occupant's routines.
  • Resources: add people, plan and activate deployments, and issue equipment. Activating a deployment issues the cubicle, laptop and apartment together.
  • Weekly reporting: the ICPM creates each reporting cycle, adds last week's PLOW and the FTE workbooks, prepares the draft, reviews it and downloads the PowerPoint.
  • Skills: reviewed Assistant skills arrive only with a BCW release. Users turn them on themselves.

Moving people already on site

To move someone who is already deployed to another BMT position, laptop or cubicle, use Manage deployment. For example, moving Jason from BMT01 to BMT05 with BMT05's laptop and a new cubicle:

  1. Open Resources → Deployments, open the person's deployment and press Edit. This opens Manage deployment.
  2. Change BMT position to the new account, e.g. BMT05. It must have no occupant. The laptop switches to that position's laptop by itself, because each laptop belongs to its BMT login.
  3. Pick the new cubicle, and an apartment or other items if they change.
  4. Check Role/Position. The person keeps the roles ticked here. When moving the ICPM, keep ICPM ticked.
  5. Press Save. The person keeps their deployment and history, and the old position's items are released.

Afterwards:

  • Password: the person now signs in with the new account, which keeps its own password. Set a new one in User accounts → Set password.
  • Old position: it is now empty but keeps its roles. Remove any you don't want under Resources → Accounts. BCW allows removing ICPM there once another account someone signs in as has it.

To change only a cubicle or other items, use the same dialog and leave the BMT position unchanged.

Don't use Transfer on the laptop to move a person. Transfer moves the person to the other account, but they take on that account's existing roles, not their own. Transferring the ICPM this way leaves ICPM on the empty old account, and nobody who signs in has the Admin tab. V0.16 allows this. From V0.17, BCW refuses with "This change would leave no enabled ICPM that anyone signs in as".

Always keep ICPM on at least two accounts people actually sign in to.

10. Improving BCW at work

The BCW program code is kept in Gitea on the Ascent (http://192.168.2.45:3000, sign-in required). This makes small fixes possible on site:

  • Codex on the Ascent or OpenCode on HAL3000 can make and test small fixes. Each fix is saved as a commit in Gitea.
  • Gitea refuses to overwrite history or delete branches, so any change can be undone.
  • Bigger changes, and every new BCW release kit, are made at home. A code fix in Gitea doesn't change the running BCW. It reaches HAL3000 in the next update kit.

Taking work fixes home:

  1. Plug the Transcend into the Ascent.
  2. Run the export command in BCW-V0.17-WORK-UPGRADE.txt, section 4.
  3. Eject the drive safely.
  4. At home, the fixes are merged with the main code.

12. Safety rules

  • Never delete, move or hand-copy BCW's data folder (Documents\BCW\data). Use Backup and Export backup.
  • Never run Install over an existing system. Use Update. Go back with Restore, never by swapping program versions.
  • Never delete lock, marker or journal files. Use the Recover actions.
  • Backups contain passwords and private records. Store exported copies securely.
  • Keep the Ascent on the isolated network, with its firewall on. Its AI services have no passwords of their own.
  • Never delete the Ascent's model files. They can't be replaced on site.
  • Leave the Ascent's automatic updates off. Make changes deliberately, with a plan.
  • Don't change HAL3000's address without renewing the HTTPS certificate.
  • Don't start a second account change to work around a failed one. Retry the same one.
